# Native CarPlay dynamic display — Build 4 investigation

2026-11-25. User requests resizing the CarPlay layout in place, without disconnecting; browser first. Do not change existing authentication, transports, MFi import, or CarLife initial sizing.

## Verified source findings
- `App/CarPlayInfo.swift` currently advertises one `viewAreas` entry and `initialViewArea: 0`; display dimensions and HID descriptor are fixed at startup.
- `App/NativeReceiver.swift` handles `/info`, `/command`, media setup and teardown. No verified native View Area transition request/acknowledgment implementation was found in the inspected receiver path.
- `App/BrowserReceiverPage.swift` and `App/Localization/Receiver.en.html` already report viewport size after resize and use aspect-fit presentation; input mapping uses the fitted picture bounds.
- Previously `ReceiverViewController.browserReportedDisplay` scheduled `adaptToPrimaryScreen`, which could stop/restart the entire CarPlay session for a changed display plan. Build 4 now guards the browser path at scheduling and execution. Reports still update stored screen profiles for future starts. Existing performance recovery is separate and unchanged.

## Official references and limitations
- https://developer.apple.com/videos/play/wwdc2019/252/ (Dynamic Screen Resizing, 6:36 onward): vehicle declares multiple view areas; CarPlay can transition between them while connected. Requires vehicle integration APIs in CarPlay Communication plug-in R15.
- https://developer.apple.com/videos/play/wwdc2023/10150/ (2:11 onward): dynamic resizing for different vehicle UI layouts; distinction between view area and safe area.
- Public presentations do not provide the exact receiver-side transition messages and acknowledgment schema required by this implementation. Do not guess wire keys, advertise unsupported capabilities, or bypass authentication. Obtain authorized integration documentation/SDK before implementing native transitions.

## Next implementation gates
1. Confirm supported transition operations, multiple view area declaration, and explicit acknowledgment using authorized technical material.
2. Design bounded, declared view area profiles and transition state machine. Keep current layout on failure, never restart because of a resize. Do not promise arbitrary pixel-level live resizing.
3. Confirm decoded image bounds, video configuration updates and touch mapping using actual negotiated area and transition progress; no stretched frames or stale touch coordinates.
4. Browser-first real-device validation (fullscreen, split, rotate, rapid resize, touch, audio, cancel); extend to CarLife only if its downstream display-size updates are supported. Preserve all other modes.

Current implementation is **presentation-only fallback**, not native layout reflow. Black margins may appear. Source tests and Swift parse are not Xcode or actual CarPlay session verification.
