# R150 — 连接模式整理与竖屏设备初始显示协商

基线：用户上传的 `DerPlay-build18-R146-all-in-one.zip`，内部源码包解压后作为本地工作树。版本元数据仍为 `0.0.1 Build18`；R150 是开发检查点，不是正式发布版本。

## 本轮实现

### 界面
- 主页入口名称统一为「通用设置」「连接模式」；连接模式页标题保持「连接模式」，协议选择项名称为「互联协议」。
- 连接模式页面拆为两个卡片：上方无分组标题，放「互联协议」与按原逻辑显示的「Wi-Fi 网络」；下方卡片标题在卡片外显示「CarPlay 设置」。
- CarPlay 设置顺序调整为「声音设置」「昼夜模式」「Dock 栏」「图标大小」「画面比例」「清晰度」「实际输出分辨率」，后续保留视频帧率/编码及原有协议专属入口。
- 右上角原关闭项改为与主页共享状态的圆形启动/停止按钮，绿色/红色玻璃配置、白色播放/停止图标；保留左侧原生返回及下滑关闭设置页。
- DerPlay 标题阴影减轻；主页 AirPlay 选择器仍使用原生 `AVRoutePickerView`，以黑色 `airplayvideo` 图形覆盖系统按钮图形，外围使用 iOS 26 Liquid Glass 圆形材质；旧系统使用 ultra-thin material 回退。系统路由选择行为未替换。

### 画面比例与清晰度
- 内置比例按用户确认的顺序固定：32:9、21:9、16:9、16:10、4:3、4:1、3:2、3:1、1:1、9:16、3:4。
- 新增比例来自已记录设备的物理屏幕尺寸（screen width/height × DPR），按最大公约数约简，去重后按横屏/正方形/竖屏分组，并按冒号前的数字降序稳定排序。旧 CarScreen 记录仍可解码。
- 清晰度弹窗只显示 480P/720P/1080P/2K/4K 档位名称；设置行改名「清晰度」。实际输出宽高单独显示。
- 新增 `DisplayGeometry`：清晰度档位作为宽高硬上限；竖屏时旋转宽高边界；在边界内按比例计算最大画布；短边不足 320 时自动调整以达到最低短边；输出宽高取偶数。720P 示例：16:9=1280×720，4:3=960×720，9:16=720×1280，9:19=606×1280，4:1=1280×320。
- 保留 CarLife 专用首帧协商和仪表固定分辨率早退路径，不把通用几何算法覆盖到这些专用模式。

### 竖屏浏览器设备的 CarPlay 首次握手
- 在本机 CarPlay + 浏览器输出 +「自动适配」模式，先启动浏览器视频 HTTP 服务，暂缓发布 CarPlay 配件监听。
- 等待期间主页提前显示可复制的 `IP:端口` 地址，接收设备先打开该地址；浏览器报告可用 viewport 像素尺寸后，DerPlay 在清晰度边界内计算输出画布，更新 `VideoOutputServer` 的编码尺寸，再启动 CarPlay 监听。
- 因此首个 CarPlay `/info` 及 HID 坐标描述使用同一实际画布尺寸；无需通过拉伸或裁切来伪装 9:19。
- 等待最长 45 秒；未报告尺寸、尺寸无效或视频输出尺寸更新失败时，回退到当前默认画布并启动，不无限等待。
- 实验性原生多 View Area 动态切换仍未启用；本轮实现的是**首次连接前的尺寸协商**，不是运行中无缝动态切换。

- `DisplayGeometrySmoke`：旋转边界、720P 9:19、320 像素最低短边、偶数对齐、动态比例排序通过。
- `CarScreenStoreSmoke`：物理屏幕尺寸存储、旧格式记录解码通过。
- 修改的 Swift 文件 `swiftc -parse` 通过；Preflight 通过；Xcode 工程生成器已包含 `DisplayGeometry.swift`。
- 尚未执行 Xcode 完整类型检查/编译、IPA 生成、签名部署或真实 CarPlay/浏览器设备测试。特别需要真机验证：浏览器先开页面并全屏的等待流程、45 秒超时、9:19 首个 `/info` 尺寸、实际全屏无拉伸、触控坐标及 AirPlay 图标材质/导航按钮过渡效果。

## 使用提示（待真机验证）
浏览器自动适配模式启动后，先在接收设备打开主页显示的访问地址；接收页面需要进入全屏（或浏览器视口已覆盖物理屏幕至少 97%）；屏幕识别完成后，DerPlay 才启动 CarPlay。如果 45 秒内未打开页面，将使用默认比例启动。手动固定比例模式不走此等待流程。
